# Map very large objects directly

Objects of OTI_LARGE_MIN or more are each a malloc (heap_alloc_large, c/src/heap.c:296), so churn in big strings/arrays fragments the system allocator. Consider mmap above some size (64 KB?) so freeing returns the memory. Leave until a workload shows a problem.

## Acceptance Criteria

A workload churning large objects keeps resident memory near its live size, or this is closed as not needed.
