# Store Code bytes and constants inline in the Code object

CodeData holds two C-heap pointers, bytes and consts (src/heap.h:69-80), allocated in make_code and freed by the collector sweep. Both sizes are fixed at creation -- len and constCount never change after make_code returns -- so neither needs to be a separate allocation at all.

Make Code one variable-sized GC object: header, CodeData, then constCount Values, then len bytes. Put the consts first so they stay 8-aligned without padding arithmetic. heap_alloc already handles variable payloads for String, and the Cheney scan already walks a dynamic count of Values for Array.

What this buys beyond removing two allocations per compiled function: Code drops off the finalizable list entirely, so the sweep no longer has to consider it, and the bytecode ends up adjacent to its constant pool in memory rather than two malloc blocks away.

This is the self-contained slice of the wider "object bulk lives in the C heap" problem (see the array/table/buffer ticket) and does not depend on it. It also subsumes the Code half of lan-goky.

## Acceptance Criteria

make_code performs no C-heap allocation. ObjType_Code is no longer pushed to the finalizable list, and the sweep and heap_deinit switches no longer mention it. Existing compile and VM tests pass under OT_GC_STRESS.
