# Add GSGC as a third collector

Transplant the GSGC 1.0 algorithm as `GC=gsgc` alongside `semi` and `gen`. Keep Otium's exact object tracing, roots, extension finalization, statistics, and collector test surface.

## Design

Keep the generation-scavenging algorithm but rewrite its collector seam around Otium. Otium has variable-sized objects whose mixed pointer and atomic layout does not fit GSGC's one-word map. Reuse `ot-gc-trace.inc` for roots and fields, route `ot_store` through GSGC's remembered set, and report the existing machine-readable counters. Extend the direct comparison to run `semi`, `gen`, and `gsgc`, with enough run metadata to append longitudinal CSV results.

## Acceptance Criteria

1. `GC=gsgc` builds and passes the common runtime, language, CLI, extension, and hygiene tests.
2. GSGC uses exact Otium roots and object-field tracing, including variable-sized slots and table entries.
3. Old-to-young stores use the GSGC remembered set.
4. Extension objects are finalized once when unreachable.
5. GC statistics and `gc_compare.py` include GSGC without changing `semi` or `gen` results.
6. Documentation records provenance, local changes, build commands, and memory-accounting limits.
