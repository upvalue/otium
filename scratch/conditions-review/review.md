## Conclusion

Keep the existing condition/control-transfer model. Fix failure-presence bugs at actor, callback, and group boundaries first, then improve diagnostic preservation. Records are useful as typed payloads or internal bookkeeping, but converting public conditions wholesale is neither necessary for Manse nor a modest change.

History supports the user's recollection: `617f654` (2026-10-16) already aligned handler/restart/cleanup semantics; `04e90ba` (2026-10-21) added fixed-layout records; `4f1246e` (2026-10-27) replaced the C runtime; `9a49fcd` (2026-10-29) added generated record accessors/constructors. `869b670`'s “structured record” is the C diagnostic structure, not conversion of language conditions to defrecord instances.

## Confirmed correctness holes, highest priority

1. **Actor `(error nil)` is silently returned as successful nil.** `lib/otium/thread.ot:261` catches a payload and writes `:error e`; table insertion of nil removes the key. `lib/otium/actor.ot:30` then matches the ordinary value reply, whose absent value defaults to nil. Independent probe: nil => `(:returned nil)`, while false and 42 => `(:caught #f)` and `(:caught 42)`. Use an explicit failure discriminator independent of the payload, with an optional payload field (or one-element envelope). Keep success nil distinct from failure nil. Update sender and receiver together to use the explicit failure discriminator. Regression tests: success nil, error nil/false/scalar/table/record; repeat calls and continued actor service.

2. **FFI callbacks lose `(error nil)` and first-error ordering.** `c/src/foreign.c:622` and `:850` use `state->values[0] == OT_NIL` as absence. A callback raising nil returns the ABI zero and the outer call reports success: `(:returned 0)`, confirmed in native and VM modes. A two-call callback raising nil then 'second reports 'second, violating documented first-error retention. False and 42 do propagate. Add a pending-condition boolean/tag separate from its rooted payload. Audit nested calls, reset/cleanup, exit and interrupt precedence. Tests should cover nil alone, nil before another error, nested callbacks, successful next call after a failure, and callback-local recovery. Preserve the existing rule that C completes before the pending error propagates; do not unwind arbitrarily across foreign frames.

3. **Thread groups ignore non-table failures.** `lib/otium/thread.ot:199` uses `(table? outcome)` to recognize failure in call-with-cleanup. For an independent group, children raising nil, false, 42, or 'oops print to stderr but closing the group returns successfully; a table condition is correctly collected and raised. Linked groups use the same filter, so sibling cancellation/owner notification is also bypassed by these payloads (source inference; only independent behavior was executed). Fix this at the library boundary with a catch-all around the child body that records any caught payload and rethrows it, retaining proper cleanup/kill ordering. Verify linked and independent groups, all payload kinds, ordinary returns, kill/exit, user cleanup failures, and the rule that errors caught inside the child do not fail the group. Avoid making a generic cleanup API treat nil as failure: nil already denotes normal cleanup and :quit denotes termination.

## Diagnostic and typing improvements

4. **Caught errors discard useful source context; dev replies further narrow fields.** `c/src/diagnostics.c:55` skips trace capture whenever a try frame exists. `c/src/conditions.c:91` converts an error to a condition without the C location/trace; VM/native catches clear the C error (`c/src/vm.c:948`, `c/src/native.c:1626`). A caught `(car 42)` contains type/message/code/who/value, but no location. `c/src/dev.ot:69` supplies only the outer evaluated form's path/line. `lib/otium/dev.ot:111` projects to type/message/irritants/source, dropping code, who, value, reason, frames, and nested failure detail. UI frame errors use that projection. First preserve available fields through a bounded, serializable diagnostic projection in Otium. If exact caught-error locations are desired, make a separately reviewed, general runtime change that preserves a small source snapshot before clearing errors; don't globally allocate full traces on every signal for the inspector. Test nested eval calls, catch/rethrow, thread causes, callbacks, records/cycles in payloads, and report-generation failure.

5. **Library error subtypes are inconsistently registered.** In a fresh process, `(condition-of-type? (thread/timeout-condition "probe") 'error)` is false, and a joined failed thread gives `(thread-failed #f)`. `lib/otium/thread.ot:64,68,196` construct timeout/thread-failed/thread-group-failed tables without define-condition. C catalog errors register lazily in `c/src/conditions.c:54`, making some type answers dependent on which errors occurred earlier. Register library-owned types explicitly when loading their module; audit ffi-error similarly. Keep `error?`'s documented table-with-type convention unchanged: it is intentionally broader than subtype-of-error. Test in fresh processes before and after related errors and after reload. Decide and document the shared symbol namespace/reparenting contract; changing it is broader than this repair.

## Records: useful, but no automatic replacement

`lib/otium/core.ot:585-605` and `c/src/conditions.c:23,195` explicitly recognize tables. Any value can already be raised; a record round-trips with identity intact, but error? returns false and condition-message returns nil. A table condition may already carry a record as data/value/reason without changing control transfer.

Records have nominal descriptor identity, fixed fields, optional shallow immutability, identity equality, and no inheritance (`specs/records.md`, `c/src/records.c`). `lib/otium/core.ot:1255` rejects changed layouts during live reload. Current conditions have extensible fields, dynamic symbol-based subtype registration, arbitrary custom tables, and mutable diagnostic decoration. `ot_report_error` even annotates an existing table with span/frames (`c/src/diagnostics.c:545`). A wholesale swap breaks getters, mutation, predicates, serializers, custom errors, and reload assumptions. The C error record also serves allocation-failure/early-runtime reporting, so it is not redundant merely because language records exist. VM/native unwind paths are separate execution backends; keep paired tests rather than merging them speculatively.

If a condition record API is later wanted, first define a stable read-only condition protocol and explicit conversion for diagnostics, retaining table compatibility. Do not add record inheritance, generic table semantics, or runtime inspector exceptions just for this.

## Crash containment and existing strengths

Conditions already support catch-all payloads, signaling before unwind, restarts, cleanup on failure/exit/interrupt, and thread-local execution state. Existing tests cover nested handler masking, restart lifetime/arguments, cleanup replacement, and errors from C builtins. Cleanup failures deliberately replace the pending error; preserving the earlier failure as suppressed diagnostic context could improve debugging, but must not change which condition/restart wins.

UI catches frame errors per window (`lib/otium/ui/window.ot:344`), records an event, clears dirty flags, and honors fail-fast/ui-teardown. This preserves the loop, not transactional application state. It deduplicates by revision/type/message; different sites with the same message can collapse. App-level last-good view/failure state and explicit retry fit better than changing the runtime for inspector recovery. No GUI behavior was executed.

Green threads share one process and heap. They contain language failures, not native memory corruption. `c/src/foreign.c:558` aborts on foreign-thread or out-of-call callbacks; blocking native calls must return before normal VM interrupt handling can help. Launcher alternate signal stacks support SIGINT/timer handling (`c/src/main.c:25-57`), not arbitrary segfault recovery. Keep unrecoverable native faults fatal. For robust native fault containment, use a separate process with external crash/core diagnostics and controlled restart; preserve app session state at the app layer. Do not attempt to catch SIGSEGV and continue the same runtime. No native-fault injection was performed.
